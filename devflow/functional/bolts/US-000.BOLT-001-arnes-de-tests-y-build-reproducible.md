## 1. Description

Se entrega la base de verificación reproducible de Cooperator 2.0 —y del árbol 1.4 congelado— junto con el gate que detecta toda ruptura de la superficie pública frente a la línea base 1.4 y la reporta para su documentación.

---

## 2. Expected outcome and completion evidence

- **Objective:** que la migración pueda demostrar que *el comportamiento no cambió* y que ninguna ruptura de superficie quede sin detectar y sin documentar, **antes** de tocar el TFM de cualquier librería.
- **Completion criterion:** el árbol 2.0 compila y ejecuta su suite desde un comando reproducible; la suite de caracterización sobre el comportamiento observable del 1.4 pasa; el gate de compatibilidad de API corre contra la línea base 1.4 y contra la línea anterior de la 2.0, y **falla** ante una ruptura introducida deliberadamente.
- **Expected evidence:** salida de la corrida reproducible (build + suite) con su versión de herramienta fijada; la **línea base 1.4** producida y versionada junto a los fixtures; dos corridas del gate —una sin rupturas (verde) y otra con la ruptura deliberada (rojo, con la ruptura identificada)—; el listado de paquetes/ensamblados generados por el árbol 2.0.
- **Scope:** la estructura de solución y la configuración de build compartida que el resto de los Bolts usa como base (ADR-001 §3.1); el proyecto o proyectos de tests; la suite de caracterización del comportamiento observable de 1.4 (contratos de datos, cifrado, validación de CUIT argentina, generación de artefactos); el **build reproducible del 1.4 congelado** (prerequisito de ADR-002 §3.2); el **gate de compatibilidad de API** con su línea base 1.4 (ADR-008 §5); la **verificación ejecutable contra dependencias reales** (SQL Server del 1.4 y del destino), como capacidad propia del arnés.
- **Exclusions:** no migra ni reescribe código de producto; no cambia los TFMs ni el mapa de paquetes ya decididos (ADR-001 §3.1); no implementa el formato `.coop2`, el motor ni el shell; no verifica contra SQL Server real el comportamiento de las capas que todavía no se migran (cada Bolt responde por la suya); no escribe las notas de migración (Bolt propio), aunque el gate las exige para estar verde.
- **Risks / controls:** *arnés que da falsa confianza* → la caracterización se define sobre el comportamiento **observable** de 1.4, no sobre el código nuevo; *la línea base 1.4 no existe como paquete* (el 1.4 se consumía por DLLs) → producirla y versionarla en este Bolt, como paso único (ADR-008 §5); *gate sin notas* → la política de ADR-008 §3.1 y el Bolt de notas de migración; *build no reproducible* → fijar versiones y herramienta, y verificar la reproducibilidad con dos corridas idénticas.
